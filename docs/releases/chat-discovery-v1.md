# 전공 기반 공지 탐색 경로 보강

2026-09-12 수정 후보. 운영에는 아직 배포하지 않았다. 최초 기준은 `codex/legacy-followup-release`의 `a87e128b9f3a949dba75cb574dd9e680756e05fd`였고, 작업 중 병합된 새 디자인을 보존하도록 최신 `main`의 `2dbd273` 위에 다시 적용했다. 기존 후속 질문의 원문 인용·서명된 카드 참조와 새 디자인을 유지하며 이 브랜치의 차이는 서버·테스트·이 문서 3개 파일이다.

## 문제와 변경

“나 컴퓨터공학부 학생인데 어떤 공지 가보는게 좋으려ㅓ나”라는 질문에 주제를 다시 요구하는 동일한 안내가 반복됐다. 기존 계획 호출은 `tool_choice: auto`였고, 도구를 선택하지 않은 모든 응답을 서버가 같은 안내로 바꿨다. 검색 판단 실패와 검색 단서 부족을 구분하지 못한 문제다.

모델은 이제 `search_posts` 또는 `chat_guidance` 중 하나를 명시적으로 선택한다. 전공·관심 주제·활동 목적만 있어도 검색을 시작하도록 프롬프트를 보강했다. 전공으로 캠퍼스·학년·활동유형이나 지원 자격을 추정하지 않는다. 사용자가 직접 말한 전공은 관련 주제 검색의 단서이며 저장 프로필이나 별도 추천 알고리즘과 연결하지 않는다.

`chat_guidance`는 인사·감사·사용법·서비스 밖 질문·검색 단서 부족의 열거형만 받는다. 실제 문장은 서버가 작성한다. 도구 누락·알 수 없는 도구·잘못된 JSON은 `SEARCH_PLAN_FAILED` 오류로 구분하며, 모델의 자유 답변이나 조건을 버린 빈 검색으로 대체하지 않는다. 이전 카드 토큰은 정상 안내에서 유지된다.

일반 검색, 추천, DB·임베딩·검색 정렬, 상세 원문 선택과 UI는 수정하지 않았다. 기존 검색 도구의 필터와 의미 검색 결합 한계는 이 수정으로 해결되지 않는다. `required`는 도구 선택을 강제하지만 올바른 의도 판단 자체를 보증하지 않는다. [공식 Function calling 안내](https://developers.openai.com/api/docs/guides/function-calling)를 참고했다.

## 검증

- 수정 전 관련 검사 11개 실패를 확인했다. 수정 후 4파일·46개, 최신 `main`에 다시 적용한 뒤 전체 **5파일·56개** 테스트가 통과했다. 도구 미선택 실패, 사용자 원문 전달과 검색 연결, 안내 이유 검증, 서명된 카드 유지, 기존 상세 인용을 포함한다.
- 타입 검사·프로덕션 빌드·변경 파일 lint가 통과했다. 기존 browser-mapping 데이터 갱신 안내는 남아 있다. 로컬 빌드에는 가짜 환경 값을 사용했고 실제 배포용 산출물이 아니다.
- 실제 요청 생성 함수를 고정하고 사용자 원문으로 GPT-4o 계획 호출을 한 번 실행했다. 반환 모델은 `gpt-4o-2024-08-06`이다. 결과는 `search_posts`와 `semantic_query: "컴퓨터공학"`이었으며 임의의 캠퍼스·활동유형 필터를 추가하지 않았다.
- 실측 입력 2,924토큰·출력 41토큰, 약 2.807초다. [GPT-4o 단가](https://developers.openai.com/api/docs/models/gpt-4o)와 예산 환율 1,600원/$에 따른 환산액은 **12.352원**, 10% 여유분 포함 장부 반영액은 **13.59원**이다. 64원 예약 후 관측 사용량으로 정산했다. 전체 관리액 **24,666.361744원**, 25,000원 중단선까지 **333.638256원** 남았다. 이전 미정산 예약은 유지했다.
- 실제 공지 검색·답변 생성·운영 API를 다시 호출하지 않았다. 이 단일 계획 확인을 추천 품질이나 전체 대화 성공률로 해석하지 않는다.
